# Macro Kit — design (1.0.0)

Macro Kit (app code **MK**) is one small Windows app that replaces three popular tools, without their extra features:

| Tool replaced | Macro Kit part | What it does |
| --- | --- | --- |
| TinyTask | **Recorder** tab | Record mouse and keyboard, save recordings, play one back at a chosen speed, once / N times / continuously. Global hotkeys. |
| PhraseExpress (autotext) | **Phrases** tab | Type a trigger such as `/shrug` anywhere and it is replaced with the saved text (`¯\_(ツ)_/¯`). |
| Stream Deck + BarRaider Super Macro | **Macros** tab + **Deck** | Write (or click together) a Super Macro script such as `{{CTRL}{C}}{{PAUSE:50}}{{ALT}{TAB}}…`, run it once / N times / continuously **in the window you choose**, never in Macro Kit itself, with Alt+Tab that never lands on Macro Kit. The Deck is a small always-on-top button panel that never takes focus (like the virtual Stream Deck). |

Not in scope ("no fluff"): TinyTask's compile-to-exe, PhraseExpress's clipboard manager, spelling, menus, sync and macro functions, Super Macro's file/icon/key-title/input-prompt commands, Stream Deck profiles.

## 1. Build and layout

- .NET Framework 4.8 WPF, UI built in C# code (no XAML compiler). Compiled with the Roslyn `csc.exe` at `C:\dev\Toolchains\VS2022\MSBuild\Current\Bin\Roslyn\csc.exe` (`-langversion:latest -platform:x64`), exactly like Tweak Bench (`C:\dev\Windows\Build.ps1` is the template). Output is one self-contained `Macro Kit.exe` plus `Macro Kit.exe.config`.
- `Build.ps1 [-OutputDirectory dir] [-Test]`: builds into the project root by default (`C:\dev\Macro Kit\Macro Kit.exe`), dot-sources the shared `Build.Common.ps1` (`_shared\` first, then `C:\dev\App Maintenance\shared`), uses `Move-BuildLeftovers`, `Copy-TransferHelper`, and ends with `Update-ProjectRoot` (skipped when `MK_STAGE_ROOT` is set for parallel private builds). Shared sources compiled in: `AppRestart.cs`, `SingleInstance.cs`, `ConfigurationTransfer.cs`, `ReleaseNotes.cs`, `ReleaseAttributes.cs`. `CHANGELOG.md` is embedded as `App.Changelog.md`, `assets\MK.png` as `App.Icon.png`, `assets\MK.ico` is the win32 icon. `-Test` also builds `MacroKit.Tests.exe` (console) from every `src` folder except `src\App` plus `tests\*.cs`. Never build installers here.
- `tools\Test-Module.ps1 -Module <Macros|Phrases|Recording|Win32|Core>` compiles `src\Core\*.cs` + `src\<Module>\*.cs` + `tests\TestKit.cs` + `tests\Fakes.cs` + `tests\<Module>Tests.cs` (+ `tests\CoreTests.cs` for Core) into a private temp folder and runs it, so parallel module work never breaks another module's build. Exit code = failures.
- `app.manifest`: `asInvoker`, PerMonitorV2 DPI awareness (so all coordinates are physical pixels), long paths, Windows 10/11 compatibility id. Copy Tweak Bench's.
- `assets\MK.ico` / `MK.png`: generated by `tools\Make-Icon.ps1` (System.Drawing; a rounded keycap with a small play triangle, accent blue on dark). Sizes 16–256.

## 2. Testing rules (non-negotiable)

- **Tests never send real input, never install real hooks, never register real hotkeys, never touch the real clipboard and never change real window focus.** SendInput from a hidden desktop would still reach the real screen. All logic is tested through `tests\Fakes.cs`.
- Anything that can open a window runs through `C:\dev\Toolchains\HiddenDesktop\Invoke-OnHiddenDesktop.ps1` (never on the visible desktop). The test exe is a console app; run it hidden too (`CREATE_NO_WINDOW`).
- When `CLAUDE_HIDDEN_DESKTOP=1`, `MK_NO_INPUT=1` or `--no-input` is passed, the app installs no hooks, registers no hotkeys, sends no input and skips the Startup registry; `--data <dir>` points it at a private data folder. A no-input session given neither `--data` nor `MK_DATA_ROOT` uses a fresh temporary data folder (and its own log folder), never the real `%LOCALAPPDATA%\Macro Kit`, and shows no dialogs. `--self-test-ui <outdir>` builds every window (main window on each tab, light and dark; Deck; run pill; changelog) with synthetic data, renders each to PNG with `RenderTargetBitmap`, writes `<outdir>\self-test.txt` with PASS/FAIL lines and exits 0 when all pass.
- Win32 tests check struct sizes (`INPUT` = 40 bytes on x64, `KBDLLHOOKSTRUCT` = 24, `MSLLHOOKSTRUCT` = 32), flag constants, extended-key table, window filter logic on fake data, and pure helpers only.
- Test launches always pass `--data` and `--no-input` (or set `MK_NO_INPUT=1`), so a test can never touch real data or input.

## 3. Core contracts (`src\Core`)

Exact public surface (implementations may add private members; do not rename these).

```csharp

{

    /// Output of keyboard and mouse input. Real: Win32.SendInputSink. Tests: Fakes.FakeInputSink.
    public interface IInputSink

        void KeyUp(ushort vk);

        void TypeText(string text);              // Unicode; '\n' = Enter key, '\t' = Tab key, '\r' dropped

    }

    /// Time. Real: SystemClock (Stopwatch + WaitHandle). Tests: FakeClock (virtual time).
    public interface IClock
    {
        long NowMs { get; }
        /// Waits ms milliseconds; throws OperationCanceledException as soon as the token is cancelled.
        void Sleep(int ms, CancellationToken token);
    }
    public sealed class SystemClock : IClock { /* Stopwatch-based NowMs; Sleep = token.WaitHandle.WaitOne(ms) then ThrowIfCancellationRequested */ }

    /// Text clipboard. Real: Win32.Win32Clipboard (OpenClipboard with retries; usable from any thread). Tests: FakeClipboard.
    public interface IClipboard { string GetText(); void SetText(string text); object Snapshot(); void Restore(object snapshot); void SetTextPrivate(string text); uint SequenceNumber { get; } }

    public sealed class WindowInfo
    {
        public IntPtr Handle; public string Title; public string ProcessName; /* "Chrome.exe" */ public int ProcessId;
        public string ClassName; public bool IsElevated; /* best effort: true when the process token says elevated or cannot be read */
        public override string ToString(); // "Title — Process.exe"
    }

    /// How a saved target window is found again. Empty fields are ignored; matching is case-insensitive.
    public sealed class WindowMatch
    {
        public string ProcessName { get; set; }    // "EXCEL.EXE"
        public string TitleContains { get; set; }  // "Book1"
        public bool IsEmpty { get; }                // an empty match matches no window
        public bool Matches(WindowInfo w);
        public string Describe();                  // "Chrome.exe, title contains “Orders”"
        public static WindowMatch From(WindowInfo w); // process name + full title
    }

    /// Windows. Real: Win32.WindowSystem. Tests: Fakes.FakeWindowSystem.
    public interface IWindowSystem
    {
        IntPtr Foreground { get; }
        WindowInfo Describe(IntPtr hwnd);                 // null when the window is gone
        IList<WindowInfo> ListSwitchableWindows();        // what Alt+Tab would show, Z-order (most recent first), excluding this process
        WindowInfo Find(WindowMatch match);               // first match in ListSwitchableWindows order, or null

        bool IsOwnWindow(IntPtr hwnd);                    // belongs to this process
        IntPtr LastExternalForeground { get; }            // most recent switchable foreground window not owned by this process
    }

    [Flags] public enum HotkeyModifiers { None = 0, Alt = 1, Ctrl = 2, Shift = 4, Win = 8 }   // = MOD_* values
    public struct Hotkey
    {
        public HotkeyModifiers Modifiers; public ushort Vk;
        public bool IsEmpty { get; }
        public static bool TryParse(string text, out Hotkey hotkey);   // "Ctrl+Shift+Alt+R", "Ctrl+Alt+1", "F13"; case-insensitive
        public override string ToString();                             // canonical order Ctrl+Shift+Alt+Win+Key
        public bool IsValidGlobal { get; } // needs Ctrl, Alt or Win, or a key F13–F24 / Pause alone; Shift-only is invalid
    }

    /// Key names shared by the parser, hotkeys and UI.
    public static class KeyNames
    {
        public static bool TryGetVk(string name, out ushort vk);   // Super Macro names and aliases, case-insensitive (table below)
        public static string Display(ushort vk);                   // "Ctrl", "Alt", "Tab", "Down", "F5", "A", "Num 5", ...
        public static string MacroToken(ushort vk);                // canonical Super Macro name: "CTRL", "ALT", "TAB", "DOWN", "C"
        public static bool IsModifier(ushort vk);                  // Shift/Ctrl/Alt/Win in generic and L/R forms
        public static bool IsExtended(ushort vk);                  // needs KEYEVENTF_EXTENDEDKEY (arrows, Ins/Del/Home/End/PgUp/PgDn, RCtrl, RAlt, Win, Apps, Divide, NumLock, PrintScreen, media/browser/volume keys)
        public static bool IsMouseButton(string name, out MouseButton b); // LBUTTON, RBUTTON, MBUTTON, XBUTTON1, XBUTTON2

```

Key name table (Super Macro's documented names first, then friendly aliases; all case-insensitive):

- Letters/digits: `A`–`Z`, `0`–`9`, and `VK_A`–`VK_Z`, `VK_0`–`VK_9`.
- `ENTER`/`RETURN`, `TAB`, `ESCAPE`/`ESC`, `SPACE`, `BACK`/`BACKSPACE`, `DELETE`/`DEL`, `INSERT`/`INS`, `HOME`, `END`, `PAGEUP`/`PGUP`/`PRIOR`, `PAGEDOWN`/`PGDN`/`NEXT`, `UP`, `DOWN`, `LEFT`, `RIGHT`, `CLEAR`, `BREAK` (Pause/Break key; the word `PAUSE` alone is the pause command, never a key), `CAPITAL`/`CAPSLOCK`, `NUMLOCK`, `SCROLL`/`SCROLLLOCK`, `SNAPSHOT`/`PRINTSCREEN`, `PRINT`, `SELECT`, `EXECUTE`, `HELP`, `APPS`/`MENUKEY`.
- Modifiers: `SHIFT`, `LSHIFT`, `RSHIFT`, `CTRL`/`CONTROL`, `LCTRL`/`LCONTROL`, `RCTRL`/`RCONTROL`, `ALT`/`MENU`, `LALT`/`LMENU`, `RALT`/`RMENU`, `WIN`/`WINDOWS`/`LWIN`, `RWIN`. Generic `CTRL`/`SHIFT`/`ALT` send the left key (`VK_LCONTROL` etc.) so Alt+Tab and shortcuts behave like a real keyboard.
- `F1`–`F24`.
- Numpad: `NUMPAD0`–`NUMPAD9`, `MULTIPLY`, `ADD`, `SUBTRACT`, `DECIMAL`, `DIVIDE`, `SEPARATOR`, and `NUMPAD_PAGEUP`, `NUMPAD_PAGEDOWN`, `NUMPAD_HOME`, `NUMPAD_END`, `NUMPAD_UP`, `NUMPAD_DOWN`, `NUMPAD_LEFT`, `NUMPAD_RIGHT`, `NUMPAD_INSERT`, `NUMPAD_DEL` (the same VKs as the navigation keys but sent **without** the extended flag).
- OEM: `OEM_1`–`OEM_8`, `OEM_102`, `OEM_PLUS`, `OEM_MINUS`, `OEM_COMMA`, `OEM_PERIOD`.
- Media/browser/volume: `MEDIA_NEXT_TRACK`, `MEDIA_PREV_TRACK`, `MEDIA_PLAY_PAUSE`, `MEDIA_STOP`, `VOLUME_UP`, `VOLUME_DOWN`, `VOLUME_MUTE`, `BROWSER_BACK`, `BROWSER_FORWARD`, `BROWSER_HOME`, `BROWSER_REFRESH`, `BROWSER_STOP`, `BROWSER_SEARCH`, `BROWSER_FAVORITES`.

`NUMPAD_*` navigation names need a distinct value so the sink sends them non-extended. Real VKs are below 0x100, so `KeyNames` returns `vk | 0x8000` for them (`KeyNames.ForceNonExtended = 0x8000`); `IsExtended` returns false for such values and the sink masks the bit off before sending. Everything that compares VKs (modifier checks, smart Alt+Tab) masks it too (`KeyNames.BaseVk(vk)`).

### Storage (`src\Core\Storage.cs`, `Paths.cs`)

- `Paths.DataRoot`: `--data <dir>` (set via `Paths.Override(dir)`) or `MK_DATA_ROOT`, else `%LOCALAPPDATA%\Macro Kit\data`. `Paths.Logs` = `%LOCALAPPDATA%\Macro Kit\logs` (machine-local, never transferred; with an override: `<data>\..\logs`).
- Files in the data folder (all JSON, UTF-8 without BOM, indented, `"Schema": 1`):
  - `settings.json` — `AppSettings` (required for transfer; written on first start).
  - `phrases.json` — `{ "Schema": 1, "Phrases": [ PhraseDef… ] }`. First start seeds one phrase: `/shrug` → `¯\_(ツ)_/¯` (Immediately).
  - `macros.json` — `{ "Schema": 1, "Macros": [ MacroDef… ] }`. First start seeds one example macro "Copy, switch, paste, next row" with the example script `{{CTRL}{C}}{{PAUSE:50}}{{ALT}{TAB}}{{PAUSE:100}}{{CTRL}{V}}{{PAUSE:50}}{{ALT}{TAB}}{{PAUSE:100}}{{DOWN}}{{PAUSE:50}}`, Repeat Times 5.
  - `recordings.json` — `{ "Schema": 1, "Recordings": [ RecordingInfo… ] }` index; `recordings\<id>.json` — one `Recording` each. The index is rebuilt from the files if it is missing or disagrees.
- Every write: write `<file>.tmp`, flush, then `File.Replace(tmp, file, file + ".previous")` (or `File.Move` when new). An unreadable file is moved aside to `<file>.unreadable-yyyyMMdd-HHmmss` and defaults are used; the UI is told (never silently overwrite user data).
- `Storage` is an instance class: `new Storage()` (uses `Paths.DataRoot`) or `new Storage(dataRoot)` (tests), with `string DataRoot`. API: `AppSettings LoadSettings()`, `SaveSettings(AppSettings)`, `List<PhraseDef> LoadPhrases()`, `SavePhrases(IEnumerable<PhraseDef>)`, `List<MacroDef> LoadMacros()`, `SaveMacros(...)`, `List<RecordingInfo> LoadRecordingIndex()`, `Recording LoadRecording(string id)`, `SaveRecording(Recording)` (updates index), `DeleteRecording(string id)`, `RenameRecording(string id, string name)`, `ExportRecording(string id, string file)`, `Recording ImportRecording(string file)` (new Id), plus `IList<string> Warnings` (a snapshot of the unreadable files moved aside this session). Missing recordings throw `FileNotFoundException` from Rename/Export; `ImportRecording` throws `InvalidDataException` with a plain message for other files. Extra helpers: `Recording.NowIso()`, `Recording.DefaultName(DateTime)`, `Storage.SeedPhrases()/SeedMacros()`. Thread-safe (one lock).
- `Json` helper (`Serialize(object)`, `Deserialize<T>(string)`, `ParseTree`, `FromTree<T>`, `HasProperty`) parses with `JavaScriptSerializer` (`MaxJsonLength = int.MaxValue`) and maps onto the models itself: enums as names, pretty-printed, recording events as compact `[t,kind,a,b]`, NaN written as null, wrong-typed or unknown values keep the class default.
- `Log` (`src\Core\Log.cs`): `Log.Info/Warn/Error(msg, ex)` to `Paths.Logs\macrokit.log`, 512 KB rotation to `.old`, never throws. Never log typed text or phrase contents (privacy): log triggers by phrase Id only.

## 4. Macros (`src\Macros`) — Super Macro compatible

### Parser

```csharp
public enum StepKind { Keys, KeyDown, KeyUp, KeyRepeat, Text, Pause, MouseMoveTo, MouseMoveBy, MouseMoveNormalized,
                       MouseDown, MouseUp, MouseClick, MouseDoubleClick, MouseWheel, SaveMousePos, LoadMousePos,
                       SetVar, OutputVar, UnsetVar, UnsetAllVars, SetClipboard, VarFromClipboard }
public sealed class MacroStep {
    public StepKind Kind; public ushort[] Keys; public string Text; public int Ms; public int X; public int Y; public int Count = 1;
    public MouseButton Button; public bool Horizontal; public string Var; public string Value;
    public int Index; public int Length; public int Line; public int Column;   // source span (Line/Column 1-based)
    public string Describe();   // "Press Ctrl+C", "Wait 50 ms", "Press Alt+Tab", "Type “hello”", "Press Down 5 times, 100 ms apart"
}
public sealed class ParseError { public int Index; public int Length; public int Line; public int Column; public string Message; }
public sealed class ParseResult { public List<MacroStep> Steps; public List<ParseError> Errors; public bool Ok { get; } public long EstimatedMs(MacroDef m); }
public static class MacroParser { public static ParseResult Parse(string script, bool newLineIsEnter); }
```

Rules:

- `{{` starts a command and `}}` ends it. Inside, either one or more `{KEY}` groups (a key combination) or one `NAME` / `NAME:args` command. Whitespace inside braces is ignored (`{{ ENTER }}` works). Command and key names are case-insensitive.
- `{{KEY}}` presses one key; `{{CTRL}{C}}`, `{{ALT}{TAB}}`, `{{CTRL}{SHIFT}{ESC}}` press every key in order and release in reverse (`IInputSink.KeyCombo`). A combo of only mouse-button names (`{{LBUTTON}}`, `{{RBUTTON}}`, `{{MBUTTON}}`, `{{XBUTTON1}}`, `{{XBUTTON2}}`) is a click.
- Everything outside commands is literal text typed as-is. Line breaks (`\r\n` or `\n`) press Enter when `newLineIsEnter`, otherwise they are skipped. A lone `{` or `}` outside a command is literal. `{{//}}` comments out the rest of its line (including the line break).
- Commands (args separated by `:`; coordinates by `,`; numbers are integers, may be negative where noted):
  - `{{PAUSE:ms}}` (0–3,600,000).
  - `{{KEYPRESS:KEY:count[:delayMs]}}` repeat a key; `{{KEYDOWN:KEY}}` / `{{KEYUP:KEY}}` hold and release (KEY may be any key name, including modifiers).
  - Mouse: `{{MOUSEXY:x,y}}` absolute pixels (0,0 = top-left of the primary monitor, negatives allowed), `{{MOUSEMOVE:dx,dy}}` relative, `{{MOUSEPOS:x,y}}` deprecated normalized 0–65535, `{{MLEFTDOWN}}` `{{MLEFTUP}}` `{{MLEFTDBLCLICK}}` `{{MRIGHTDOWN}}` `{{MRIGHTUP}}` `{{MRIGHTDBLCLICK}}` `{{MMIDDLEDOWN}}` `{{MMIDDLEUP}}`, `{{MSCROLLUP[:n]}}` `{{MSCROLLDOWN[:n]}}` `{{MSCROLLLEFT[:n]}}` `{{MSCROLLRIGHT[:n]}}` (default 1 notch), `{{MSAVEPOS}}` (sets `$MOUSE_X`/`$MOUSE_Y`), `{{MLOADPOS}}`.
  - Variables (live for one run, across its repeats): `{{VARSET:name:value}}`, `{{OUTPUT:name}}` (types it; `$name` also accepted), `{{VARUNSET:name}}`, `{{VARUNSETALL}}`, `{{SETCLIPBOARD:value}}`, `{{VARSETFROMCLIPBOARD:name}}`. Inside command arguments `$Name` is replaced by the variable's value at run time; predefined `$SMCOLON` `:`, `$SMDOLLAR` `$`, `$SMLCB` `{`, `$SMRCB` `}`, `$SMSPACE` space, `$SMENTER` Enter (typed as the Enter key by OUTPUT), `$MOUSE_X`, `$MOUSE_Y`. Unknown `$Name` → empty.
  - Known Super Macro commands Macro Kit does not support (`INPUT`, `OUTPUTTOFILE`, `APPENDTOFILE`, `VARSETFROMFILE`, `VARSETFROMENV`, `SETICONFROMFILE`, `SETKEYTITLE`, `RUN`, `PLAYSOUND`, functions/loops) → error "`{{INPUT}}` is a Super Macro command Macro Kit doesn't support." Unknown names → "Unknown key or command “FOO”." Errors carry the span; the runner refuses to run a script with errors.
- The example script `{{CTRL}{C}}{{PAUSE:50}}{{ALT}{TAB}}{{PAUSE:100}}{{CTRL}{V}}{{PAUSE:50}}{{ALT}{TAB}}{{PAUSE:100}}{{DOWN}}{{PAUSE:50}}` must parse to exactly 10 steps and be a test case.
- `MacroScript.Token(...)` helpers build the canonical text the palette inserts (`{{CTRL}{C}}`, `{{PAUSE:100}}`, `{{KEYPRESS:DOWN:5:100}}`, `{{MOUSEXY:100,200}}`…), round-trip with the parser.

### Runner

```csharp
public sealed class RunProgress { public int Pass; public int TotalPasses /* 0 = continuous */; public int StepIndex; public int StepCount; public string Message; }
// RunResult { bool Completed; bool Cancelled; string Error; int PassesDone } is defined in src\Core\Models.cs (the recording Player returns it too); the Macros module must not redefine it.
public sealed class MacroRunner {
    public MacroRunner(IInputSink input, IWindowSystem windows, IClock clock, IClipboard clipboard);
    public event Action<RunProgress> Progress;
    /// Blocking; call from a background thread. Never throws (errors go to RunResult.Error).
    public RunResult Run(MacroDef macro, ParseResult parsed, RunOrigin origin, CancellationToken token);
}
```

Run sequence:

1. Refuse when `parsed` has errors or no steps.
2. **Resolve the target window.** `SpecificWindow`: `windows.Find(macro.TargetWindow)`; none → error "Can't find the window to run in (Chrome.exe, title contains …). Open it and try again." `PreviousWindow`: origin `MainWindow`/`Tray` → `LastExternalForeground`; origin `Deck`/`Hotkey` → `Foreground` unless it is our own window or `IWindowSystem.IsSwitchable` says Alt+Tab would not list it (taskbar, desktop, Start menu, task switcher), else `LastExternalForeground`. Nothing usable → error "Click the window you want the macro to run in first."
3. **Alt+Tab partner.** When `AltTabPartner` is not empty: `Find` it (none → error naming it). The partner must differ from the target.
4. If origin is `Hotkey`, wait (≤ 3 s, cancellable) until Ctrl, Shift, Alt and Win are physically released.
5. **Prime focus.** With a partner: `Activate(partner)` then `Activate(target)` so the system's recent-window order is target → partner (a real Alt+Tab then also goes to the partner). Without: `Activate(target)` when it is not already foreground. A failed activation → error "Windows didn't let Macro Kit switch to <window>." Warn (Progress message, not an error) when the target `IsElevated` and Macro Kit is not: Windows blocks input to apps running as administrator.
5a. **Target ready.** Still on the worker thread, once per run and before the first step, the runner calls `TargetReady(token)`. The shell uses it to hide the main window: it posts the hide to the UI thread with `BeginInvoke` and waits on a `ManualResetEventSlim` (at most 1 s, honouring the run's token; never `Dispatcher.Invoke`, so Stop, Exit and Dispose cannot deadlock with it). If hiding moved the focus, the runner activates the target again. So a real Alt+Tab as the very first step can never meet a visible Macro Kit window.
6. **Passes.** `Once` = 1; `Times` = `RepeatTimes` (1–100000); `Continuous` until cancelled. `RepeatDelayMs` between passes (not after the last). Raise `Progress` at each pass and step.
7. **Steps.** After every step that sends input wait `KeyDelayMs`. `Pause` waits its ms. All waits go through `IClock.Sleep(ms, token)` so Stop is immediate.
   - **Smart Alt+Tab:** a `Keys` step that is exactly {Alt or LAlt or RAlt, Tab} and a partner is set does not send keys: it switches with `Activate(other)` where other = partner when the foreground is the target, else target; if `Activate` fails within 500 ms it falls back to the real Alt+Tab keys and checks the foreground became `other`. `Describe()` stays "Press Alt+Tab"; Progress says "Switching to <window>".
   - **Focus guard:** before each input step: if the foreground is a Macro Kit window, or (when `Target == SpecificWindow && StopIfFocusLeaves`) the foreground is neither the target nor the partner, poll for up to 750 ms (focus may still be settling after Alt+Tab); still wrong → stop with error "Stopped because <title> took focus." Real Alt+Tab without a partner is allowed to land anywhere except Macro Kit: with a specific window and no partner, the first window an Alt+Tab settles on is learned as the "other" window and only those two are allowed afterwards; a third window or Macro Kit stops the run.
8. **Always clean up** (finally): release every key and mouse button this run pressed and has not released (`KeyDown`/`MouseDown` steps, cancelled combos).
9. `Cancelled` when the token was cancelled; `Completed` when every pass finished.

## 5. Phrases (`src\Phrases`) — text expansion

```csharp
// KeyEvent is defined in src\Core\Events.cs (namespace MacroKit.Core): the Win32 hook, Phrases and Recording all share it.
public struct KeyEvent { public ushort Vk; public ushort Scan; public bool Down; public bool Injected; public bool Extended; public long TimeMs; }
public sealed class ExpansionEngine
{
    public ExpansionEngine(IInputSink input, IClipboard clipboard, IClock clock);
    public bool Enabled { get; set; }
    public void SetPhrases(IEnumerable<PhraseDef> phrases);           // thread-safe snapshot swap
    public void SetExcluded(IEnumerable<string> processNames);         // plus Macro Kit's own process, always
    /// Called on the hook thread for every keyboard event. typed = the characters this key produces (null/empty when none),
    /// foregroundProcess = "notepad.exe". Returns true to swallow the event. Must be O(phrases) with no I/O or waiting.
    public bool OnKey(KeyEvent e, string typed, string foregroundProcess);
    public void Reset();                                               // mouse click, foreground change, Enabled change
    public event Action<PhraseDef> Expanded;                           // raised on the worker thread after typing finished
    public bool IsExpanding { get; }
    public void Dispose();                                             // stops the worker thread
}
```

Behaviour:

- Ignore injected events (`Injected`) entirely: Macro Kit's own output, macros, playback and other tools never trigger or disturb expansion. Ignore everything when disabled or when the foreground process is excluded (Macro Kit's own windows always excluded, so editing a trigger in Macro Kit never expands it).
- Rolling buffer (last 64 chars) of what was typed in the current field: `typed` chars are appended on key-down; Backspace removes one char (Ctrl+Backspace clears); Escape, arrows, Home, End, PgUp/PgDn, Delete, Insert clear; Ctrl/Alt/Win shortcuts that produce no character clear (AltGr characters arrive as `typed` and are kept); `Reset()` clears.
- **Immediately** phrases (default): when the buffer ends with the trigger (case-insensitive unless `MatchCase`; anywhere, even inside a word, like PhraseExpress "execute immediately") the final key-down is **swallowed** (return true) and its matching key-up is swallowed too; the expansion sends `trigger.Length - 1` Backspaces and then the replacement.
- **AfterDelimiter** phrases: the trigger must be preceded by the buffer start, whitespace or punctuation, and followed by a delimiter key (space, Enter, Tab, or a punctuation character). The delimiter key-down/up is swallowed; the expansion sends `trigger.Length` Backspaces, the replacement, then the delimiter itself (Enter key / Tab key / the character).
- The longest matching trigger wins. The buffer is cleared after an expansion.
- Expansion runs on the engine's own worker thread (never the hook thread). While it runs, physical key events are swallowed and queued (vk + down/up), then replayed in order through the sink when the expansion has finished, so fast typing is not lost or interleaved.
- `InsertMethod.Type`: `TypeText(replacement)`. `InsertMethod.Paste`: wait (≤ 300 ms) until Ctrl/Alt/Win/Shift are physically released, `Snapshot()` the whole clipboard, `SetTextPrivate(replacement)` (text plus the `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory` = 0 and `CanUploadToCloudClipboard` = 0 formats, so it never reaches Win+V history or cloud sync), `KeyCombo(Ctrl, V)`, wait 250 ms, then `Restore(snapshot)` (also marked private) unless another program copied something in the meantime (`SequenceNumber` changed). If the clipboard cannot be written, nothing is erased and the last key is typed back; if typing or pasting fails after the Backspaces, the erased part of the trigger is typed again and `ExpansionFailed` is raised (no phrase text in the message).
- Any exception in the worker is logged and resets the buffer; the hook path never throws.
- The shell ignores the keyboard for the engine while a macro or playback runs (and resets it once when the run starts), so a phrase can never paste over the macro's clipboard or interleave its keys.

The character a key produces is computed by the Win32 hook (`ToUnicodeEx` with flag 4 = do not change keyboard state, using the foreground thread's keyboard layout and a key-state array built from `GetAsyncKeyState` for Shift/Ctrl/Alt and the CapsLock toggle) and passed as `typed`. Dead keys produce nothing until the composed character.

## 6. Recording (`src\Recording`) — TinyTask style

```csharp
// MouseEventKind and MouseEvent are defined in src\Core\Events.cs (namespace MacroKit.Core), shared with the Win32 hook.
public enum MouseEventKind { Move, Down, Up, Wheel, HWheel }
public struct MouseEvent { public MouseEventKind Kind; public MouseButton Button; public int X; public int Y; public int Delta; public bool Injected; public bool OverOwnWindow; public long TimeMs; }
public sealed class Recorder
{
    public Recorder(IClock clock);
    public bool IsRecording { get; }
    public void Start(bool recordMouseMoves);
    public void OnKey(KeyEvent e);      // hook thread; ignores injected
    public void OnMouse(MouseEvent e);  // hook thread; ignores injected; a Down over a Macro Kit window is dropped with its matching Up
    public Recording Stop(IEnumerable<Hotkey> hotkeysToStrip);
}
public sealed class PlaybackProgress { public int Pass; public int TotalPasses; public int EventIndex; public int EventCount; public int ElapsedMs; public int DurationMs; }
public sealed class Player
{
    public Player(IInputSink input, IClock clock);
    public event Action<PlaybackProgress> Progress;   // at most ~10 per second
    public RunResult Play(Recording rec, PlaybackSettings settings, CancellationToken token);   // blocking, never throws
}
```

- Times are ms since `Start`. Moves closer than 1 ms to the previous move are merged. Key auto-repeat key-downs are kept (TinyTask does) but a key-down for a key already down is recorded only once per 30 ms.
- `Stop` cleans up: drops key-ups at the start whose key-down was not recorded (keys held when recording began, e.g. the record hotkey); drops trailing key events of the keys in `hotkeysToStrip` (the stop hotkey's modifiers and key, generic and L/R forms); `DurationMs` = last event time (≥ 0). Name defaults to "Recording yyyy-MM-dd HH:mm".
- Playback schedules each event at `start + T / Speed` (Speed 0.1–100) against `IClock.NowMs` (no drift accumulation). When behind schedule, consecutive moves are coalesced to the latest one; clicks, wheel and keys are never dropped. `RepeatMode` as for macros with `RepeatDelayMs` between passes. On finish or cancel, every key and button still down is released. Moves use `MouseMoveTo`.

## 7. Win32 (`src\Win32`)

- `Native.cs`: every P/Invoke and struct. `INPUT` with `[StructLayout(LayoutKind.Explicit)]` union at offset 8 on x64 (size 40); `KEYBDINPUT`, `MOUSEINPUT`, `HARDWAREINPUT`, `KBDLLHOOKSTRUCT`, `MSLLHOOKSTRUCT`. `SetLastError = true` where useful.
- `SendInputSink : IInputSink`: keys with `MapVirtualKey(vk, MAPVK_VK_TO_VSC)` scan codes and `KEYEVENTF_EXTENDEDKEY` from `KeyNames.IsExtended` (honouring the force-non-extended bit); `KeyCombo` downs in one `SendInput`, 15 ms, ups reversed in one `SendInput`; `TypeText` with `KEYEVENTF_UNICODE` (surrogate pairs as two units; `\n` → VK_RETURN, `\t` → VK_TAB) in batches of ≤ 64 characters; `MouseMoveTo` = `SetCursorPos`; `MouseMoveBy` = `GetCursorPos` + `SetCursorPos`; buttons/wheel via `MOUSEINPUT` (`XBUTTON1/2` in `mouseData`); `MouseMoveNormalized` via `MOUSEEVENTF_MOVE|MOUSEEVENTF_ABSOLUTE`. Every event carries `dwExtraInfo = 0x4D4B4954` ("MKIT"). Throw `InvalidOperationException` when `SendInput` returns fewer events than sent (UIPI/blocked).
- `InputHook`: one dedicated background thread with its own message loop installs `WH_KEYBOARD_LL` and `WH_MOUSE_LL` (`SetWindowsHookEx(..., GetModuleHandle(null), 0)`), keeps the delegates alive, and calls subscribers synchronously: `Func<KeyEvent, string, bool> KeyHandler` (returns swallow) and `Action<MouseEvent> MouseHandler`. It computes `typed` (ToUnicodeEx as in §5) only for non-injected key-downs. Must stay fast: no allocation-heavy work, no locks held long, exceptions caught. `Injected` = `LLKHF_INJECTED` / `LLMHF_INJECTED`. `OverOwnWindow` = the root window under the point belongs to this process. Also hosts `SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT)` for foreground tracking and a message-only window for `RegisterHotKey` (`MOD_NOREPEAT`), so hooks, hotkeys and foreground events share one thread. `Start()`, `Stop()` (unhook, unregister, end the loop), `bool RegisterHotkey(int id, Hotkey hk, out string error)`, `UnregisterHotkey(int id)`, `event Action<int> HotkeyPressed`, `event Action<IntPtr> ForegroundChanged` — events raised on the hook thread (subscribers marshal to the UI).
- `WindowSystem : IWindowSystem`: `ListSwitchableWindows` = `EnumWindows` (Z-order) filtered to visible, non-empty title, not cloaked (`DwmGetWindowAttribute(DWMWA_CLOAKED)`), no owner or `WS_EX_APPWINDOW`, not `WS_EX_TOOLWINDOW` unless `WS_EX_APPWINDOW`, not shell windows (`Shell_TrayWnd`, `Shell_SecondaryTrayWnd`, `Progman`, `WorkerW`, task switcher `XamlExplorerHostIslandWindow`, `MultitaskingViewFrame`, `ForegroundStaging`), not this process. Process name via `QueryFullProcessImageName` (`PROCESS_QUERY_LIMITED_INFORMATION`). `IsElevated` via `OpenProcessToken`/`TokenElevation`, true when access is denied. `LastExternalForeground` from the foreground events (only windows that pass the switchable filter; seeded with the current foreground at start). `Activate`: `IsIconic` → `ShowWindow(SW_RESTORE)`; `SetForegroundWindow`; if the foreground did not change, `AttachThreadInput` (this thread ↔ foreground thread) + `BringWindowToTop` + `SetForegroundWindow` + detach; poll `GetForegroundWindow` every 10 ms until `timeoutMs`. Never simulate an Alt tap (Excel shows KeyTips).
- `WindowStyles`: `MakeNoActivate(IntPtr hwnd)` (adds `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`, clears `WS_EX_APPWINDOW`) and an `HwndSource` hook helper returning `MA_NOACTIVATE` for `WM_MOUSEACTIVATE`; `HideFromAltTab(IntPtr hwnd, bool hide)`.
- `Win32Clipboard : IClipboard` (`OpenClipboard` retried 10× 20 ms, works from any thread). `Snapshot` copies every HGLOBAL format (not GDI-handle or COM-backed ones; text only above 64 MB); `SetTextPrivate` adds the history/cloud exclusion markers in the same open session.
- `StartupEntry`: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` value `Macro Kit` = `"<exe>" --tray`; `IsEnabled`, `Enable(exe)`, `Disable()`.
- `Elevation.IsCurrentProcessElevated`.

## 8. App shell (`src\App`)

- `Release.Version = "1.0.0"` (single version source; `AppIdentity` points at it), `AppIdentity` Code `MK`, ShortName `Macro Kit`.
- `Program.Main`: `--version`, `--changelog` (attach to parent console like Tweak Bench), `--self-test-ui <dir>`, `--data <dir>`, `--no-input`, `--tray` (start hidden in the tray), `AppRestart.Argument` handoff. Single instance (`Local\MacroKit.App` mutex via `SingleInstance.TryAcquire`; a second launch signals `Local\MacroKit.App.Show` so the running window comes forward). Refuse to start while the Configuration Transfer window is open (`SingleInstance.TransferWindowOpen()`).
- `AppController` owns storage, the hook, the engines and **one activity at a time** (Recording, Playing, Running macro): starting another while one runs is refused with a status message; Stop (button, pill, Deck, tray, Stop hotkey, physical Esc when `EscStops` and not recording) cancels it. Hotkeys: Record toggles recording; Play starts/stops the selected recording; Stop stops anything; Deck toggles the Deck; each macro's own hotkey starts it (or stops it when it is the one running). Hotkey registration failures are shown in Settings next to the hotkey ("Another app already uses Ctrl+Alt+1").
- **Getting out of the way (the focus requirement).** Before any run or recording starts from the main window: remember `LastExternalForeground`, then activate the target (the runner does this) and **hide the main window** (it disappears from Alt+Tab and the taskbar; tray stays). The Deck and the run pill are no-activate tool windows: they never take focus and never appear in Alt+Tab. When the activity ends, the main window comes back only if it was visible before the run (and `ShowWindowAfterRun`, or there is no tray), and it never takes focus or covers the window being worked in: if it was minimized it returns minimized (`SW_SHOWMINNOACTIVE`, the window state is never set to Normal); otherwise it is shown without activation and immediately placed with `SetWindowPos(…, SWP_NOACTIVATE | SWP_NOMOVE | SWP_NOSIZE)` directly behind the foreground window when the run started from the main window, or at `HWND_BOTTOM` for Deck, hotkey and tray runs (also when the foreground window is always-on-top), so it is not first in Alt+Tab either. Only explicit opens (tray, second launch, the end of a window pick) set `WindowState = Normal` and activate, using `IWindowSystem.Activate` with its fallback rather than plain WPF `Activate`.
- **Cancellation exists from the start.** `Begin` creates the run's `CancellationTokenSource` before anything slow (hiding, activating), so an Esc pressed during start-up always stops the activity. A macro run hides Macro Kit through `TargetReady` (see the run sequence); recording and playback hide it synchronously before the worker starts.
- **Could not start.** A macro, recording or playback that cannot start (parse error, nothing to run, another activity running) is shown in the status line, and when it was not started from the main window (hotkey, Deck, tray) also flashes on the run pill for about 5 s, because Macro Kit may be hidden in the tray.
- **Administrator windows.** When Macro Kit is not elevated and the window a recording or playback works in (the foreground window if Alt+Tab would list it, else the last window used) runs as administrator, the status line and the run pill say: "This window runs as administrator, so Windows blocks Macro Kit's input there. Run Macro Kit as administrator to use it with that window." (Macros warn through the runner's progress message.)
- **Own windows and the hook.** After each of the main window, Deck and run pill gets its handle (or closes) the shell calls `InputHook.SetOwnWindows`, so clicks and wheel turns over Macro Kit are not recorded; the hook never calls `WindowFromPoint`.
- **Hotkey capture.** While a global-hotkey box has keyboard focus every registered hotkey is released (`SuspendHotkeys`/`ResumeHotkeys`, counted), so pressing an assigned combination reaches the box; duplicates are still reported live. The "Repeat a key" box accepts one plain key and shows a hint when a modifier is held.
- **Window picking.** "Pick" and the open-window list store only the program name and leave "Title contains" empty (window titles hold document names), showing "Picked: <title>. Add a title filter only if you have several windows of this program open." The window being picked is never the taskbar, desktop, Start menu, task switcher or Macro Kit (`IsSwitchable`), for the automatic pick and for "Use this window" (which also names the window already in front, which the automatic pick cannot detect).
- **Run pill**: small topmost no-activate tool window, by default at the bottom-right of the work area of the monitor the target is on (18 px in). Dragging its background or text (`DragMove`; a click that moves it under 3 px is ignored) saves its outer rect in physical pixels as `PillLeft/Top/Right/Bottom`; from then on it is placed there, keeping the edges nearest the screen edges of the half it was dropped in (so it grows away from them as its text changes) and clamped into that monitor's work area. A saved rect that is no longer on any screen falls back to the corner. Settings → Status popup: *Show popup* shows it with nothing running ("Status popup", Done button) on the main window's monitor until Done or an activity starts; *Reset position* clears the saved rect. Examples: "Running “Copy rows” · pass 3 of 10 · Stop (Ctrl+Shift+Alt+S)" / "Recording… 0:12 · Stop (Ctrl+Shift+Alt+R)" / "Playing “Login” · 2.0× · pass 1". Its Stop button works without stealing focus.
- **Deck**: topmost no-activate tool window; a drag strip with the title and a close (hide) button; a grid (`DeckColumns`) of buttons for macros with `ShowOnDeck` (name, highlighted while running; click = run in the window that has focus, click while running = stop), one "▶ <selected recording>" button and a "■ Stop" button. Position remembered. Toggle from the header, tray and Deck hotkey.
- **Main window** (light/dark following Windows unless set; Tweak Bench's `Theme.cs`/`Ui.cs` look may be adapted): header with name + version, status line, **Deck** toggle, **Restart**, **⋯** menu (Export / import configuration…, Changelog, Open data folder). Tabs: **Recorder**, **Phrases**, **Macros**, **Settings**.
  - *Recorder*: big ● Record / ▶ Play / ■ Stop buttons with their hotkeys; recordings list (name, length, created) with the unsaved "New recording" on top until saved; Save, Rename, Delete, Export file…, Import file…; playback: Speed (slider 0.1×–100× plus ½× 1× 2× 5× 10× buttons), Repeat Once / [N] times / Continuously, delay between repeats; Record mouse movement; Save new recordings automatically.
  - *Phrases*: "Expand phrases as I type" switch; list (trigger, first line of replacement, enabled); editor: Trigger, Replacement (multi-line, monospace), Expand immediately / after a space or punctuation, Match case, Insert by typing / pasting (pasting restores clipboard text only); New, Delete. A warning row if `phraseexpress.exe` is running ("PhraseExpress is also running; both may expand the same trigger").
  - *Macros*: list (name, repeat summary, hotkey, deck); editor: Name; **script box** (monospace, multi-line) with a **command palette** that inserts at the caret — keys in labelled, colour-tinted rows (Clipboard: Copy, Cut, Paste, Select all; Switch: Alt+Tab, Ctrl+Tab; Edit: Enter, Tab, Esc, Backspace, Delete; Arrows; Jump: Home, End, PgUp, PgDn; F keys: picker + Add; tints are the KeyClip/KeySwitch/KeyEdit/KeyArrow/KeyJump theme keys), **Pause** (ms box + 50/100/250/500/1000), **Type text** (box), **Custom shortcut** (press keys to capture), **Repeat key** (key × count, delay), **Mouse** (left/right/double click, move to X,Y with "pick position" countdown, scroll), **Hold/release key**, **Comment**; a live **Steps** list (Describe() lines, errors in red with line/column, estimated time per pass); Repeat Once / [N] times / Continuously + delay between repeats; Delay between keystrokes; New lines press Enter; **Run in**: (•) the window I used before Macro Kit / (•) a specific window [open-window dropdown + **Pick** (click the window you want; Macro Kit returns) + editable process / title-contains]; **Alt+Tab switches to**: (•) whatever Windows picks (Macro Kit is never picked) / (•) a specific window [same picker]; Stop if another window takes focus; Hotkey (press keys); Show on Deck; Run / Stop; New, Duplicate, Delete.
  - *Settings*: the four global hotkeys, Esc stops playback and macros, Close button keeps Macro Kit running in the tray (phrases and hotkeys need it running), Start with Windows, Show Macro Kit again after a run, Theme, Programs where phrases never expand, Deck columns.
- Edits save automatically (~500 ms debounce); a failed save shows "Unsaved" in the header and Restart refuses until it saves. A data file that exists but could not be read this session (`Storage.ReadOnlyFiles`) is never overwritten: the header shows "Data file in use" and Settings and the status line say which file.
- **Restart** (header and tray): refuses while an activity runs ("Stop the macro first"); saves (an unsaved recording that cannot be saved also refuses); sets environment variables the replacement inherits (`MK_DATA_ROOT` when a data folder is overridden, `MK_NO_INPUT=1` in a no-input session, `MK_START_HIDDEN=1` when the main window is hidden in the tray; `Program` honours them and clears `MK_START_HIDDEN` so later launches are unaffected), then `AppRestart.Prepare()` and shuts down; the new instance waits for the old to exit before taking the mutex (hooks and hotkeys are released by then). Never runs an installer.
- **Export / import configuration…**: like Tweak Bench (`AppShared.ConfigurationTransfer.Find(appFolder, true)` + `Start(helper, appFolder, Paths.DataRoot, true)`), then Macro Kit closes itself (after saving) because the helper requires it closed; say so before closing.
- **Tray** (`System.Windows.Forms.NotifyIcon`, MK icon): Open Macro Kit, Show/Hide Deck, Stop, Phrases on/off, Restart, Exit. Exit really quits (stop activity, save, unhook). If the latest changes or an unsaved recording could not be saved, Exit asks "Your latest changes could not be saved. Exit anyway?" and stays open on No (no dialogs in a no-input session). The window's close button with the tray off (or unavailable) does not close the window inside its own `Closing` event (that throws): it cancels the close and queues `Exit` on the dispatcher; `Quit` ends in `Application.Shutdown()` in a `finally`, which closes the main window, so the process always ends. Starting a new recording while an earlier one is still unsaved asks first (main window) or is refused with a message (hotkey, Deck). No balloon notifications.
- **Changelog** window shows the embedded `CHANGELOG.md`.
